# הוספת מתכון

> **איפה זה יושב:** `YAHEALTHYbackend/data/recipes.json`
> **קובץ דאטה, לא קוד.** מתכון חדש לא דורש שינוי קוד ולא deploy — רק עריכת הקובץ.
> **מי צורך:** `GET /api/recipes` · `/api/recipes/:id` · `/api/recipes/shuffle` · מסך `RecipesPage` · ובוטי השף ונורי כסטנדרט לטון.

## 🎯 הרף — וזו כל הנקודה

**אתה מוכר ליווי שף ב-₪149 לחודש. מתכון בלי טמפרטורה וזמן הוא לא מוצר.**

לכל שלב שיש בו חום:

| חובה | דוגמה |
|---|---|
| **טמפרטורה או עוצמת חום** | `"temp_c": 200` או `"heat": "בינוני-גבוה"` |
| **זמן** | `"minutes": 35` |
| **סימן מוכנות** | `"cue": "מזלג נכנס בלי התנגדות"` |

> **🔴 "עד שמוכן" זו לא הוראה. "עד שהבצל שקוף" זו הוראה.**
> **סימן המוכנות הוא מה שמבדיל בין מתכון למוצר.** בלעדיו אין סיבה לשלם.

### וריאציות טכניקה — איך זה עובד

צלייה ב-200 מעלות עובדת על **כל ירק**: דלעת, כרובית, ברוקולי, גזר, שורש סלרי. **אותם שלבים, אותם סימני מוכנות, חומר גלם אחר.**

זה לא מילוי — **זה מה ששף באמת עושה.** מתכון כזה מקבל:
-  — מאיזו טכניקה נגזר
- - **והתאמה אמיתית:** דלעת מתוקה ומקרמלת מהר · ברוקולי צריך ייבוש · שום נשרף ונכנס מאוחר

**וריאציה שרק מחליפה שם ירק בלי להתאים — לא עברה את הרף.**

## מה שואלים — ורק מה שחסר

**אל תחקור על מה שכבר נמסר.** אם הודבק מתכון מלא — חלץ ממנו ושאל רק על הפערים.

| שדה | אם חסר |
|---|---|
| שם | שאל |
| קטגוריה | הסק מהמנה, ציין את ההנחה |

## 🔴 מה שלא ממציאים

**קלוריות.** לא יודע → אל תנחש. עדיף שדה חסר ממספר שגוי שמופיע באפליקציה כעובדה.

**טמפרטורות בטיחות.** עוף **74°C** · בשר טחון **71°C** · דג **63°C**. מתכון עם בשר או דג **חייב** `"safety"`, ואלה המספרים — לא משנים אותם.

**זמנים.** לא בטוח כמה זמן לוקח — שאל. מתכון שנכשל אצל המשתמש גרוע מלא להוסיף אותו.

## המבנה — להעתיק ולמלא

```json
{
  "id": "recipe_9",
  "name": "שם בעברית",
  "name_en": "English Name",
  "category": "breakfast | main | salad | side | snack",
  "difficulty": "easy | medium | hard",
  "time_minutes": 30,
  "calories": 320,
  "servings": 2,
  "vessel": "איזה כלי, ולמה דווקא הוא",
  "ingredients": [
    { "item": "רכיב", "amount": "כמות מדויקת", "category": "ירקות | חלבון | שומן | דגנים | תבלינים | חומצה | אחר" }
  ],
  "steps": [
    {
      "step": 1,
      "text": "מה עושים, בלשון ציווי",
      "temp_c": 200,
      "heat": "בינוני-גבוה",
      "minutes": 8,
      "cue": "איך יודעים שהשלב הסתיים"
    }
  ],
  "tips": ["2-4 טיפים"],
  "chef_note": "הדבר האחד שקובע את התוצאה",
  "safety": "רק במתכון עם בשר/עוף/דג"
}
```

**`temp_c` לתנור · `heat` למחבת.** שלב בלי חום (קיצוץ, ערבוב) — שניהם מיותרים.
**`id` רץ:** הבא אחרי האחרון בקובץ.

## מה שהופך מתכון לטוב

**`chef_note` היא לא סיכום.** היא הדבר האחד שקובע:

> *"השקשוקה נקבעת בשלב 4, לא בביצים. רוטב שלא הסמיך — ביצה טובה לא תציל אותו."*

**הטיפים הם הטעויות הנפוצות**, לא עובדות כלליות:

> *"מלח רק בסוף — מלח מוקדם מוציא מים מהעגבניות והרוטב יוצא דליל."*

**`vessel` מסביר למה דווקא הוא:**

> *"ברזל יצוק — אוגר חום ולא מתקרר כשמניחים עליו."*

**קרא 2–3 מתכונים קיימים בקובץ לפני שאתה כותב.** הטון שם הוא הסטנדרט.

## הזרימה

1. **קרא את הקובץ** ומצא את ה-`id` האחרון
2. **חלץ מה שנמסר**, שאל **רק** על מה שחסר — במיוחד טמפרטורות וסימני מוכנות
3. **הצג את ה-JSON המלא** ועצור לאישור
4. **הוסף לקובץ** אחרי אישור מפורש
5. **אמת** (למטה)
6. **סכם:** מה נוסף, מה הנחת, ומה נשאר חסר

## ✅ אימות — חובה, לא אופציונלי

```bash
cd YAHEALTHYbackend

# 1. JSON תקין, ואין id כפול
node -e "
const r=require('./data/recipes.json');
const ids=r.map(x=>x.id);
console.log('recipes:',r.length,'| unique ids:',new Set(ids).size===ids.length);
r.forEach(x=>{
  const heated=x.steps.filter(s=>s.temp_c||s.heat);
  const cued=x.steps.filter(s=>s.cue);
  if(heated.length && !cued.length) console.log('  ⚠️ no doneness cue:',x.name);
  if(/עוף|בשר|דג|chicken|fish|meat/i.test(x.name) && !x.safety) console.log('  ⚠️ missing safety:',x.name);
});
"

# 2. ה-API באמת מחזיר אותו
ALLOW_MEMORY_DB=true PORT=5000 node index.js &
curl -s localhost:5000/api/health
```

**JSON שבור מפיל את השרת בעלייה** — `index.js` קורא את הקובץ עם `JSON.parse` בטעינה. **אימות אינו טקס.**

## 🔒 כללי-ברזל

1. **טמפרטורה/חום + זמן + סימן מוכנות** לכל שלב עם חום. **זה הרף.**
2. **לא ממציאים קלוריות.** לא ידוע → שואלים או משאירים בחוץ.
3. **טמפרטורות בטיחות לא משתנות.** עוף 74 · טחון 71 · דג 63.
4. **לא כותבים לקובץ בלי להציג את ה-JSON ולקבל אישור.**
5. **מאמתים אחרי כל הוספה.** JSON שבור = שרת שלא עולה.
6. **מעתיקים את הטון של הקיים** — קוראים 2–3 לפני שכותבים.
7. **עברית טבעית**, לשון ציווי, בלי ז'רגון של שפים.
8. **מתכון אחד בכל פעם.** חמישה ביחד → חמישה בינוניים.
