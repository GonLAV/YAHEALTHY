# ספר הסקייל — מה "מנוסה בסקייל גבוה" אומר בפועל

> ⚠️ **לכתוב בפרומפט "אתה מהנדס מאוד מנוסה" לא משפר פלט.** מה שמשפר: אילוצים קונקרטיים, מספרים, וסדר-פעולות מחייב. זה הקובץ הזה.

## חוק אפס — לא מדביקים פתרונות של ענק על פרויקט מוקדם

YAHEALTHY הוא **7,508 שורות backend, מחציתן בקובץ אחד, בלי DB קבוע ובלי בדיקות.**
Kubernetes, sharding, microservices, event sourcing, CQRS — **אסורים בשלב הזה.** הם לא פותרים את הצוואר הנוכחי ומוסיפים חוב.
מהנדס סקייל אמיתי מכיר בשלב שבו המערכת נמצאת. **הצעה שלא מתאימה לשלב היא סימן לחוסר ניסיון, לא לניסיון.**

## סדר הפעולות — לא מדלגים

**1 → 2 → 3 → 4. לא מתחילים ב-3.**

| # | שלב | מה עושים | למה קודם |
|---|---|---|---|
| **1** | **עמידות** | להפסיק לאבד דאטה: DB קבוע, `USE_MEMORY_DB` שצועק במקום לשתוק, env מאומת בעלייה | מערכת שמאבדת דאטה לא "לא-מסקיילת" — **היא שבורה** |
| **2** | **נראות** | לוג מובנה עם request-id, זמני תגובה, שיעור שגיאות, health check אמיתי | **בלי מדידה אין אופטימיזציה — יש ניחוש** |
| **3** | **צווארי בקבוק** | לתקן את מה ש-2 הראה. N+1, אינדקסים חסרים, payload מנופח, סריקות ליניאריות | רק עכשיו יש דאטה להחליט |
| **4** | **קיבולת** | caching, תורים לעבודה כבדה, connection pooling, אופקיות | הכי אחרון, והכי יקר |

## מספרי-סף — מתי מותר להגיד "זה מסקיילי"

**אסור להצהיר על ביצועים בלי מדידה.** יעדים לשלב הנוכחי:

| מדד | יעד |
|---|---|
| p95 קריאת API | < 200ms |
| p99 קריאת API | < 500ms |
| p95 כתיבה | < 400ms |
| שיעור שגיאות | < 0.1% |
| קריאות DB לכל בקשה | ≤ 3 (יותר מזה — כנראה N+1) |
| גודל תשובה ברירת-מחדל | < 100KB (מעבר לזה — pagination) |
| זמן עלייה עד מוכן | < 5s |

**אין מדידה → "לא נמדד", לא "מהיר".**

## תבניות שהצוות מיישם — מהזול ליקר

1. **Pagination על כל רשימה.** אין endpoint שמחזיר הכל.
2. **אינדקס על כל שדה שמסננים לפיו.** לפני caching, לא אחרי.
3. **קריאה אידמפוטנטית, כתיבה עם מפתח אידמפוטנטיות** לכל מה שכסף או בריאות נוגעים בו.
4. **Timeout + retry עם backoff** על כל קריאה חיצונית. בלי retry אינסופי.
5. **Circuit breaker** לפני שירות חיצוני שיכול להיתקע.
6. **Cache רק אחרי מדידה**, עם TTL מפורש ומדיניות פינוי כתובה.
7. **תור לעבודה כבדה** (דוחות, ייצוא, התראות) — לא בתוך מחזור הבקשה.
8. **Graceful shutdown** — לנקז חיבורים לפני יציאה.

## דגלים אדומים — עצור ואמור בקול

- שאילתה בתוך לולאה (N+1)
- `SELECT *` על טבלה שגדלה
- endpoint בלי pagination
- `await` סדרתי על קריאות בלתי-תלויות (אמור להיות `Promise.all`)
- state במשתנה מודול — שובר כל ריצה מרובת-תהליכים
- סוד בקוד או ב-fallback של `process.env`
- **fallback שבולע שגיאה בשקט** ← הליקוי מספר 1 כאן

## הגבול הבריאותי — גובר על ביצועים

חישוב שנוגע ביעד משקל, גירעון קלורי או המלצה תזונתית (`utils/health-calculations.js`) — **לא מאיצים אותו על חשבון נכונות, ולא מטמיעים בו לוגיקה שנותנת ייעוץ אישי.** cache על תוצאה בריאותית אישית — רק עם TTL מפורש ואישור מפורש. עדיף איטי ונכון מאשר מהיר ומזיק.
