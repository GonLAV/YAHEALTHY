# הוספת פיצ'ר לאפליקציה קיימת

> **העיקרון:** הפיצ'ר החדש צריך להיראות כאילו נכתב על ידי מי שכתב את שאר הקוד. **וכל השאר נשאר ללא נגיעה.**
> זה skill להרחבת קוד קיים — **לא להתחלת פרויקט חדש ולא לריפקטור.**

---

## שלב 1 — ללמוד את הקוד לפני שכותבים מילה

**לפני שנוגעים בקובץ אחד:** למצוא פיצ'ר שכבר דומה למבוקש — קומפוננטה דומה, route דומה, ישות דאטה דומה. **להעתיק את הצורה של משהו שעובד עדיף כמעט תמיד על להמציא דפוס חדש**, כי אז הפיצ'ר מתיישב באופן טבעי: אותו מבנה תיקיות, אותן מוסכמות שמות, אותה גישה לניהול state, אותה דרך לקרוא ל-backend, אותו סגנון טיפול בשגיאות.

**ב-YAHEALTHY אתה לא מתחיל מאפס — יש מפה מדודה:**

| מה | איפה |
|---|---|
| **המלאי המלא** — 82 endpoints, 13 ישויות, 5 מסכים | `${CLAUDE_PLUGIN_ROOT}/skills/dev-team/references/project-atlas.md` |
| מצב הקוד והליקויים | `${CLAUDE_PLUGIN_ROOT}/skills/dev-team/references/codebase-map.md` |
| **מי הבעלים של כל שכבה** | `${CLAUDE_PLUGIN_ROOT}/skills/dev-team/references/team-charter.md` |
| הכרעות שנסגרו | `${CLAUDE_PLUGIN_ROOT}/skills/dev-team/references/decisions.md` |

⚠️ **התיעוד בריפו לא אמין.** `PROJECT_STATUS.md` ו-`README.md` מתארים מערכת בוגרת ומחוברת יותר ממה שקיים. **הקוד קובע.** המפה נמדדה ב-17/09/2026 — אמת מול הקוד לפני שאתה מסתמך.

### הדפוסים הקיימים — אלה שצריך לחזור עליהם

**Backend (`index.js`):**
```js
app.post('/api/thing', auth.authMiddleware, async (req, res) => {
  try {
    const schema = z.object({ /* ... */ });
    const data = schema.parse(req.body);
    const row = await db.createThing(req.user.userId, data);   // ← זהות מהטוקן
    return res.json(row);
  } catch (error) {
    if (error instanceof z.ZodError) {
      return res.status(400).json({ error: 'Invalid input', details: error.issues, requestId: req.id });
    }
    res.status(500).json({ error: 'Failed', details: safeErrorDetails(error), requestId: req.id });
  }
});
```

**ארבע מוסכמות שאין לחרוג מהן:**

1. **`auth.authMiddleware` על כל endpoint** שנוגע בדאטה של משתמש. 72 מתוך 82 עושים את זה.
2. **זהות מ-`req.user.userId` בלבד** — **אף פעם** מ-`req.params`/`query`/`body`. 79 שימושים בקוד, אפס חריגות. **זה מה שמונע IDOR.**
3. **סינון לפי בעלים בכל שליפה לפי `:id`** — `db.getThingById(req.user.userId, id)`, לא `getThingById(id)`.
4. **ולידציית zod על כל קלט.**

**Frontend:** כל קריאת רשת עוברת דרך `src/services/api.ts` (124 שורות) — **זו נקודת המינוף. אל תקרא ל-fetch ישירות מקומפוננטה.** אימות דרך `hooks/useAuth.tsx`, מסכים מוגנים ב-`PrivateRoute`.

**אם הקוד מערבב דפוסים** — קח את **החדש או הנפוץ**, לא את הישן. `crm-*.js` נראים חדשים אבל הם **קוד מת ושבור** (מייבאים `db.js` שלא קיים, ESM בפרויקט commonjs). **אל תעתיק מהם.**

## שלב 2 — תוכנית קצרה לפני קוד

**כמה שורות מספיקות.** אילו קבצים ייגעו או ייווצרו בכל שכבה, ומה הגישה הכללית. זו לא מפרט פורמלי — **זו בדיקת שפיות** שתופסת הנחה שגויה (מודל דאטה לא נכון, מקום לא נכון ל-route, בדיקת הרשאה חסרה) לפני שהיא נאפית לתוך הקוד.

**הבקשה עמומה בצורה שמשנה את התוכנית מהותית → שואלים, לא מנחשים.**

**ב-YAHEALTHY, התוכנית חייבת לענות גם על:**

| שאלה | למה |
|---|---|
| **מי הבעלים של השכבה?** | `team-charter.md`. חוצה כמה שכבות → נחמיה. משנה מבנה → VLAD |
| **צריך ישות דאטה חדשה?** | ADR-001 קבע **Supabase**. אין סכימה בקוד ואין מיגרציות — **זה עזרא, ואין דפוס להעתיק** |
| **החוזה משתנה?** | `openapi.js` **חייב** להתעדכן, אחרת ה-frontend נשבר בשקט |
| **🩺 נוגע בדאטה בריאותית?** | משקל · שינה · צום · שתייה · שאלונים → ראה השער למטה |

## שלב 3 — לממש מקצה לקצה

לבנות את הפיצ'ר בכל שכבה שהוא נוגע בה, **ולחבר אותן כך שזה באמת עובד — לא רק מתקמפל.**

**דאטה:** להוסיף או לשנות מודל **רק אם הפיצ'ר צריך דאטה חדשה.** ⚠️ **ב-YAHEALTHY אין מיגרציות ואין סכימה בקוד** — הישויות הן מפות ומערכים ב-`utils/database.js`. **אין "סגנון מיגרציה קיים" להעתיק.** צריך שינוי מבנה → **זה עזרא (`/be-data`)**, לא אתה.

**API:** להוסיף את ה-route לפי הדפוסים הקיימים לוולידציה, אימות ותשובות שגיאה. **`safeErrorDetails(error)` ולא `error.message`** — הוא מסתיר מבנה פנימי בייצור.

**Frontend:** קומפוננטה או מסך לפי הדפוסים הקיימים לעיצוב, state ושליפת דאטה. **כל מסך שמושך דאטה חייב שלושה מצבים: טעינה · שגיאה · ריק.** חסר אחד — לא גמור. **אין error boundary באפליקציה** — חריגה ברנדר מפילה את הכל.

### להישאר בגבול הפיצ'ר

**מפתה "לתקן" קוד לא קשור או לרפקטר משהו סמוך בדרך — להתנגד לזה**, אלא אם זה נדרש באמת למימוש. **נראה שווה לתקן? לציין בנפרד ולא לעשות.**

**זה כלל-ברזל של הצוות, לא המלצה.** יש בריפו ליקויים מוכרים (`crm-*.js` שבור, `index.js` בן 3,517 שורות) — **הם לא מתוקנים אגב פיצ'ר.**

### 🩺 השער הבריאותי — גובר על כל שיקול טכני

הפיצ'ר מציג **המלצה תזונתית אישית, יעד משקל, גירעון קלורי או הבטחת תוצאה?**
**עוצרים ואומרים.** לא מטמיעים לוגיקה כזו בלי אישור מפורש. `utils/health-calculations.js` — **לא מאיצים אותו על חשבון נכונות.**
דאטה בריאותית מזוהה = **מידע רגיש.** ראה `docs/compliance-register.md`.

## שלב 4 — לבדוק ולאמת

להוסיף או לעדכן בדיקות שמכסות את ההתנהגות החדשה, **לפי מסגרת הבדיקות של הפרויקט — לא להכניס מסגרת חדשה.**

### ⚠️ מה שמסגרת הבדיקות של YAHEALTHY באמת מכילה

| | מצב בפועל |
|---|---|
| בדיקות יחידה | **אין. אפס. בשום שפה** |
| בדיקות frontend | **אין** |
| מה שכן קיים | `YAHEALTHYbackend/test-system.sh` — **bash + curl + jq**, מפעיל את השרת בעצמו (שורה 90) |
| להריץ | `cd YAHEALTHYbackend && ALLOW_MEMORY_DB=true npm test` (דורש `jq`) |

**לכן "לפי הסגנון הקיים" = להוסיף בדיקה ל-`test-system.sh`**, לא להתקין Jest/Vitest.
**חושב שצריך מסגרת בדיקות אמיתית? זו החלטה של VLAD וכלב (`/qa`) — לא החלטה אגב פיצ'ר.**

### להריץ בפועל — לא להסתכל על הקוד

```bash
# Backend — לוודא שעולה ושעונה
cd YAHEALTHYbackend && ALLOW_MEMORY_DB=true PORT=5000 node index.js
curl -s localhost:5000/api/health

# בדיקת מערכת
cd YAHEALTHYbackend && ALLOW_MEMORY_DB=true npm test

# Frontend — type-check אמיתי
cd YAHEALTHYFrontend && npx tsc --noEmit
```

⚠️ **`ALLOW_MEMORY_DB=true` הוא חובה מקומית.** השרת **מסרב לעלות** בלי Supabase או בלי הדגל — בכוונה, כדי שדאטה לא תיעלם בשקט.

### 🔴 מה שלא לנסות להריץ

| פקודה | מצב |
|---|---|
| `npm run lint` (backend) | **לא קיים** ב-`package.json` |
| `npm run lint` (frontend) | **שבור** — הסקריפט קיים, אבל **eslint לא מותקן ואין קונפיג** |
| `npm run build` (frontend) | עובד — מריץ `tsc -b && vite build` |

**הבדיקה הסטטית האמיתית היא `npx tsc --noEmit`.** אל תתקין eslint כדי "לתקן" את זה — **זו הרחבת סקופ.** לציין ולהמשיך.

## שלב 5 — לסכם

**סיכום קצר ופשוט:** מה נוסף או שונה **לפי שכבה** · החלטות ששווה לסמן · ומה שהמשתמש/ת אולי ירצו בהמשך.

**דוגמה לניסוח הנכון:**

> **דאטה:** נוסף `mealReminders` ל-`memoryDb` — **אין מיגרציה, כי אין מיגרציות בפרויקט.** צריך סכימה אמיתית ב-Supabase → `/be-data`.
> **API:** `POST` ו-`GET /api/meal-reminders` ב-`index.js`, לפי דפוס `food-logs` — zod, `authMiddleware`, סינון לפי `req.user.userId`. `openapi.js` עודכן.
> **Frontend:** `MealRemindersPage.tsx`, מוגן ב-`PrivateRoute`, קריאות דרך `services/api.ts`. שלושת המצבים קיימים.
> **בדיקות:** נוספו 3 בדיקות ל-`test-system.sh`. `npm test` עובר. `tsc --noEmit` נקי.
> **לסימון:** לא הוספתי הגבלת קצב ייעודית — שאר ה-endpoints בקבוצה הזו מסתמכים על `apiLimiter` הגלובלי. **מסמן במקרה שזה מכוון.**
> **בהמשך:** אין בדיקות יחידה, אז הכיסוי הוא ברמת מערכת בלבד.

**מה שהופך סיכום לטוב:** לומר מה **לא** עשית ולמה, לא רק מה שעשית.

## 🔒 כללי-ברזל

1. **מעתיקים דפוס קיים** — לא ממציאים חדש. הדפוס החדש/הנפוץ, לא הישן. **לא מ-`crm-*.js` — הם מתים.**
2. **תוכנית לפני קוד.** עמום בצורה שמשנה את התוכנית → שואלים.
3. **נשארים בגבול הפיצ'ר.** תיקון סמוך → מציינים, לא עושים.
4. **זהות מהטוקן. סינון לפי בעלים. ולידציית zod.** אין חריגות.
5. **חוזה שהשתנה → `openapi.js` מתעדכן**, ואהליאב מתוייג.
6. **מריצים בפועל** — לא מסתכלים על הקוד. `ALLOW_MEMORY_DB=true` מקומית.
7. **לא מכניסים כלים חדשים** — לא Jest, לא eslint, לא ORM. זו החלטה של VLAD.
8. **🩺 השער הבריאותי גובר** על כל שיקול טכני.
9. **diff ואישור מפורש לפני כל שינוי קובץ.** אישור קודם לא נחשב לשינוי הבא.
